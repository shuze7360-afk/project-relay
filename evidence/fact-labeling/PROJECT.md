# 项目定义：课程小研究《两种排序算法性能对比》

## 目标与背景

- 【用户要求】比较快速排序与冒泡排序的性能，最终交付一份对比报告和一份可复现的测试脚本。
- 【用户要求】实验资源只有一台普通笔记本，代码只能使用 Python 标准库。
- 【用户提供·未核实】“快速排序一定比冒泡排序快得多，直接用快排就行。”本项目将其改写为待验证主张：在本项目定义的输入场景和实现条件下，快速排序是否始终明显快于冒泡排序。
- 【假设】课程小研究以运行时间为主要性能指标；若后续课程要求还包括内存、复杂度证明或指定报告格式，再调整范围。
- 【假设】两种算法都由项目脚本实现，不直接用 `list.sort()` 或 `sorted()` 代替被测算法；标准库排序可仅用于结果正确性校验。

## 范围

### 做什么

- 明确定义两种被测算法的实现版本和公平比较规则。
- 在同一台笔记本、同一 Python 环境中，用相同输入副本测试两种算法。
- 设计固定随机种子、多个输入规模和有代表性的输入分布，并进行重复测量。
- 测试前校验两种算法输出正确；计时只覆盖约定的被测代码段。
- 用标准库生成可保存、可追溯的原始结果，并在报告中说明方法、结果、局限和有条件的结论。

### 不做什么

- 本次框架搭建不创建测试脚本、不运行基准测试、不生成数据、不撰写研究结论。
- 不比较除快速排序和冒泡排序之外的其他排序算法。
- 不使用 NumPy、pandas、matplotlib、pytest 等第三方库。
- 不做多机器、云端或不同硬件平台的横向比较。
- 不把尚未运行的计划、理论预期或同学说法写成实验结果。

## 交付物与验收标准

1. **可复现测试脚本**（计划文件名：`benchmark_sorts.py`）
   - 仅导入 Python 标准库。
   - 能通过明确的命令行参数或脚本内集中配置，固定随机种子、输入规模、输入分布和重复次数。
   - 每轮给两种算法传入内容相同且彼此独立的数据副本；先验证排序正确，再记录计时。
   - 输出包含复现实验所需的配置、Python/平台信息及逐项测量结果；输出格式待协议阶段确定。
   - 验收方法：在项目支持的 Python 版本上实际运行代表性的小规模复现命令，退出码为 `0`，正确性检查通过，且用同一配置可再次生成结构一致、参数可核对的结果。计时数值本身不要求逐次完全相同。

2. **对比报告**（文件格式与名称待确认）
   - 包含研究问题、待验证主张、算法实现说明、实验环境、输入设计、计时方法、原始结果出处、汇总结果、解释、局限和结论。
   - 明确区分实测结果、解释和未验证推断；结论限定在实际测试场景内，不写“必然”“所有情况”等超出证据的表述。
   - 验收方法：报告中的配置和结果可追溯到脚本及原始输出；按报告给出的步骤能完成一次小规模复现；所有表格数字可从原始结果重新核对。

## 约束与授权

- 硬约束：仅一台普通笔记本；仅使用 Python 标准库；最终交付报告与可复现脚本。
- 资源原则：先用小规模冒烟测试验证正确性，再按笔记本可承受的运行时间逐级扩大；实际规模不得在运行前虚构。
- 公平性原则：固定环境与配置、复用同一组输入内容、隔离数据副本、记录预热与重复策略，并保存原始测量值。
- 本次授权：只创建或更新 `AGENTS.md`、`PROJECT.md`、`STATE.md`，不得开始算法实现、实验运行、数据分析或报告撰写。
- 后续授权：用户明确要求继续后，可在本目录创建代码和研究产物、运行本地标准库脚本并维护状态记录。
- 必须另行确认：向外部平台提交或发布、发送给他人、安装软件或依赖、改动本项目目录之外的文件。

## 阶段方案

### 阶段 1：冻结比较协议

- 产出：在 `PROJECT.md` 或届时新建的非空方法文件中确定快速排序/冒泡排序的具体实现、输入分布与规模、重复与预热策略、计时边界、输出格式和停止条件。
- 验收：协议逐项可执行，待验证主张能被测量结果支持或反驳，且所有设计符合标准库和单笔记本约束。

### 阶段 2：实现并执行可复现实验

- 产出：`benchmark_sorts.py`、正确性检查结果、环境信息和原始测量结果。
- 验收：先通过小规模正确性与复现检查，再完成协议规定的实测；运行命令、退出码、配置和结果文件均写入状态记录。

### 阶段 3：分析并形成报告

- 产出：对比报告及其引用的结果表。
- 验收：报告数字可追溯到原始结果，结论回答研究问题并明确适用边界，复现步骤在当前产物上实际通过。
