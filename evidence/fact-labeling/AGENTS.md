# 《两种排序算法性能对比》项目入口

本项目用于完成课程小研究《两种排序算法性能对比》；当前仅完成项目框架，实际进度以 [STATE.md](STATE.md) 为准。

## 阅读顺序

1. 先读本文件，了解接力规则。
2. 再读 [STATE.md](STATE.md)，确认当前任务、证据和唯一下一步。
3. 按需读 [PROJECT.md](PROJECT.md)，核对目标、范围、验收标准、约束与决定。

## 文件职责

| 文件 | 唯一职责 |
|---|---|
| `AGENTS.md` | 项目入口、阅读顺序和接力规则 |
| `PROJECT.md` | 项目目标、范围、交付物、验收标准、约束、阶段和决定 |
| `STATE.md` | 当前任务状态、证据、阻塞、未决问题和唯一下一步 |

当前不预建测试脚本、报告或实验记录；进入相应阶段后再创建实际产物。

## 接力规则

- 任务状态只使用：**待做 / 进行中 / 待验收 / 完成 / 阻塞**。
- “待验收”转为“完成”必须有对应当前版本的实际运行结果（含关键输出与退出码）或用户明确验收；只写了验证命令、只有旧证据或只有文件存在，都不能算完成。
- `STATE.md` 的“下一步”始终只保留一个，并写齐：**行动、所需输入、预期产物、完成条件**。
- 外部发布、提交或发送必须查到回执才算完成；结果不明时先查回执，不重复执行。
- 产生可验收结果、关键决定变化、遇到阻塞、中断恢复或准备交接时，主动更新 `STATE.md`；目标、范围或关键决定变化时同步更新 `PROJECT.md`。
- 记录与实际产物冲突时，以实际产物为核验对象，但不默认其正确；先核对或重验受影响部分，再修正记录。
- 恢复项目时先核对核心文件和所引用产物是否存在，不能把框架、计划或模拟结果写成真实研究证据。
