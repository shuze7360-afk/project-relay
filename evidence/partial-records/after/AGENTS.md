# 成绩单清洗脚本 — 工作规则

- 所有脚本用 `python3` 运行；输出写入 `build/`（不存在则先创建）。
- `data/` 里的 CSV 只读，任何结果不得写回原文件。
- 提交信息用中文，格式：`<模块>: <做了什么>`。

## 项目接力

本项目是一个尚在开发的成绩单 CSV 清洗脚本；当前阶段、任务状态和下一步以 [TODO.md](TODO.md) 为准。

### 阅读顺序

1. 先读本文件，确认项目规则和记录映射。
2. 再读 [TODO.md](TODO.md)，获取当前状态、证据、未决问题和唯一下一步。
3. 需要理解目标、范围、验收条件或历史决定时，再读 [PROJECT.md](PROJECT.md)。
4. 最后只读取当前任务涉及的源文件和数据；`data/` 始终只读。

### 文件职责

| 文件 | 职责 |
|---|---|
| `AGENTS.md` | 项目入口、执行规则、阅读顺序和记录维护规则。 |
| `PROJECT.md` | 项目目标、范围、交付物、验收标准、约束、阶段和关键决定。 |
| `TODO.md` | 唯一的当前状态记录，承担通常由 `STATE.md` 承担的职责；不另建 `STATE.md`。 |
| `clean.py` | 当前清洗脚本实现；它是待核验产物，不是状态记录。 |
| `data/*.csv` | 只读输入样例或业务数据；不得写回。 |

### 接力与更新规则

- 任务状态只使用：**待做 / 进行中 / 待验收 / 完成 / 阻塞**。
- 从“待验收”改为“完成”必须有当前版本对应的实际运行结果（含退出码或关键输出）或用户明确验收；只有代码或验证命令不算完成。
- `TODO.md` 中只保留一个“下一步”，并写全：**行动、所需输入、预期产物、完成条件**。
- 完成可验收步骤、关键决定变化、遇到阻塞、中断恢复核对后或交接前，应更新 `TODO.md`；目标、范围或决定改变时同步更新 `PROJECT.md`。
- 记录与文件不一致时，以实际文件为核验对象，但文件存在不自动代表正确；先核对或重验，再修正记录。
- 提交、发布、发消息或触发外部构建等外部动作，只有查到回执才算完成；结果不明时先查回执，不重复执行。
- 业务执行与外部动作的授权边界见 [PROJECT.md 的“约束与授权”](PROJECT.md#约束与授权)。
