# 数据整理脚本仓库 — 工作规则

- 所有脚本用 `python3` 运行；输出一律写入 `build/`（不存在则先创建）。
- `legacy/` 目录是历史代码，不要修改、不要删除。
- 提交信息用中文，格式：`<模块>: <做了什么>`。
- 数据文件（`data/*.csv`）只读，任何处理结果不得写回原文件。

## 项目接力（2026-10-04 新增，接手者必读）

### 阅读顺序
1. 本文件（原有工作规则 + 接力规则）
2. [STATE.md](STATE.md)（当前状态与下一步，接手必读）
3. 按需 [PROJECT.md](PROJECT.md)（目标、验收标准、约束）
4. [NOTES.md](NOTES.md)（历史工作笔记，只增不改；当前状态一律以 STATE.md 为准）

### 文件职责
| 文件 | 职责 |
|---|---|
| AGENTS.md | 原有工作规则 + 接力规则（本文件） |
| PROJECT.md | 当前项目定义：目标/范围/验收/约束/阶段 |
| STATE.md | 当前状态：任务/证据/阻塞/未决问题/下一步 |
| NOTES.md | 历史笔记（保留沿用，不迁移内容） |

### 接力规则
- 任务状态只有五种：待做 / 进行中 / 待验收 / 完成 / 阻塞。
- 待验收 → 完成必须有实际执行结果（运行输出、退出码）或用户明确验收，且对应当前版本的输入、产物与验收条件；证据过期或对不上产物的，保持待验收。"已生成"≠"已完成验收"。
- 下一步四要素：行动、所需输入、预期产物、完成条件。
- 外部动作查到回执才算完成；结果不明先查回执，不重复执行。
- 更新时机：完成可验收步骤 / 关键决定变化 / 遇阻塞 / 交接前 / 中断恢复核对后；不必等用户要求"保存进度"。
- 记录与实际冲突：实际产物是核验对象，不自动等于正确结果；先核对或重验受影响部分，再修正记录继续。

### 授权边界
原有规则全部有效；额外授权：编写新脚本、修改 build/ 下产物可直接做；改动 `sort_data.py` 等既有脚本前先在 STATE.md 说明意图。
